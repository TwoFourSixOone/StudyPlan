# Proposal：学习目标管理

> **Change ID**: `2026-10-31_learning_goal`  
> **创建日期**: 2026-10-31  
> **状态**: 草案

---

## 1. 需求背景

智学伴系统已完成基础架构搭建、学生认证、数据导入三个 change。数据库中已有知识点、题目、先修关系、课程标准等基础数据，科目表（`subject`）也已创建。

根据产品规则 #1，学习目标是整个学习闭环的起点："设定目标 → Agent 规划每日计划 → 完成每日作业 → 知识点评测 → 考试试卷分析 → Agent 动态调整计划"。当前系统缺少目标管理功能，无法支撑后续的规划 Agent 调用。

本 change 实现学习目标的完整 CRUD 与科目查询接口，为后续计划生成提供前置数据支撑。

---

## 2. 核心目标

1. **学生端**：支持创建、查看、修改、结束学习目标
2. **科目查询**：支持查询可用科目列表（供目标创建时选择）
3. **业务规则约束**：确保目标与科目绑定、同一学生同一科目仅一个活跃目标、科目需有已启用知识点才可创建目标
4. **管理端**：支持查看目标列表（按学生/科目/状态筛选）

---

## 3. 功能范围

### 包含

- **学生端接口**（JWT 鉴权，`/api/student/goal`）：
  - 创建学习目标（指定科目、学习方向、目标分数、目标周期）
  - 查看当前活跃目标（支持按 subjectId 过滤，N2）
  - 查看目标列表（含历史目标，分页）
  - 查看目标详情
  - 修改目标（学习方向、目标分数、结束日期）
  - 结束目标（状态改为 completed）
- **科目接口**（JWT 鉴权，`/api/student/subject`）：
  - 查询可用科目列表（仅返回有已启用知识点的科目）
- **管理端接口**（JWT 鉴权，`/api/admin/goal`）：
  - 查询目标列表（按学生/科目/状态筛选，分页）
  - 查看目标详情
  - 管理端不做 studentId 所有权过滤，仅做 tenantId 隔离
  - 管理端 tenantId 从 `StudentContext.getTenantId()` 获取（N1：Demo 阶段复用学生上下文，后续引入管理员 RBAC 时重构）
- **业务校验**：
  - 科目必须存在
  - 科目下必须有 ≥1 个 `active` 状态的知识点（规则 #1 边界条件）
  - 同一学生同一科目不能有多个 `active` 状态的目标
  - 目标周期结束日期必须晚于开始日期
  - 仅目标所有者可操作自己的 goals（学生端）
  - 已过期/已完成的目标不可修改

### 不包含

- 目标删除（学习记录只读不删，目标同理，仅通过状态流转）
- 目标到期自动过期（Demo 阶段不实现定时任务，由管理端手动标记或后续 change 实现）
- 目标创建后自动触发 Agent 生成计划（后续 change 实现）
- 前端页面（仅提供 API，管理后端前端与小程序端均不在本 change 范围）

## 4. 隐性约定检查

根据 `docs/architecture/implicit-contracts.md`，本 change 涉及以下隐性约定：

| 约定 | 说明 | 本 change 实现方式 |
|------|------|-------------------|
| 约定 #1：统一响应结构 | 所有接口返回 `Result<T>` | Controller 层包装返回值 |
| 约定 #2：异常处理规范 | 业务异常使用 `BusinessException` | 校验失败抛出 BusinessException |
| 约定 #3：分页参数规范 | page 从 1 开始，size 默认 10 | 使用 `PageResult<T>` |
| 约定 #4：时间格式规范 | 使用 `LocalDateTime` | 实体类字段类型 |
| 约定 #7：tenant_id 隔离 | 所有查询携带 tenant_id | 从 StudentContext 获取（管理端复用同一上下文，N1） |

---

## 5. 风险评估

| 风险项 | 可能性 | 影响 | 缓解措施 |
|--------|--------|------|----------|
| 同一学生重复创建同科目目标 | 高 | 中 | Service 层唯一性校验（student_id + subject_id + status=active） |
| 科目无已启用知识点时创建目标 | 中 | 高 | 创建前查询 knowledge_point 表校验 |
| 目标修改时已过期 | 低 | 中 | 修改前校验 status 与 end_date |
| 学生操作他人目标 | 低 | 高 | 所有学生端接口通过 StudentContext 获取 studentId，查询时强制过滤 |
| 管理端 tenantId 获取方式 | 中 | 高 | Demo 阶段复用 StudentContext（N1），后续引入管理员 RBAC 时重构为通用 UserContext |

## 6. 验收标准

- [ ] 学生可创建学习目标（指定科目、方向、目标分数、周期）
- [ ] 创建目标时校验科目存在且有已启用知识点
- [ ] 创建目标时校验同学生同科目无重复 active 目标
- [ ] 创建目标时校验 startDate 不早于今天
- [ ] 学生可查看当前活跃目标（判定口径：status=active 且 endDate>=today）
- [ ] 活跃目标支持按 subjectId 过滤（N2：多科目场景）
- [ ] 无活跃目标时返回 `Result.success(null)`，前端展示“暂无活跃目标”（I2）
- [ ] 学生可查看目标列表（含历史，分页）
- [ ] 学生可查看目标详情
- [ ] 学生可修改目标（方向、分数、结束日期）
- [ ] 修改时校验目标状态为 active 且未过期
- [ ] 修改时结束日期只能延长不能缩短
- [ ] direction 传空字符串可清空，传 null 不修改
- [ ] 学生可结束目标（状态改为 completed）
- [ ] 科目查询接口返回有已启用知识点的科目列表（GROUP BY 聚合查询）
- [ ] 管理端可查看目标列表（按学生/科目/状态筛选，分页，不做所有权过滤）
- [ ] 管理端可查看目标详情（仅 tenantId 隔离）
- [ ] 管理端 tenantId 从 `StudentContext` 获取（Demo 阶段复用，N1）
- [ ] 学生端返回的 GoalVO.studentId 恒为当前登录学生，不存在越权泄露（N3 安全断言）
- [ ] 所有接口返回 `Result<T>` 统一结构
- [ ] 所有查询携带 tenant_id
- [ ] 单元测试覆盖 Service 核心逻辑
- [ ] 集成测试覆盖 Controller 接口
- [ ] 编译通过，测试通过
