# Proposal：学生端年级设置

> **Change 名称**：`2026-11-10_student_grade_setting`
> **创建日期**：2026-11-10
> **版本**：v1
> **状态**：待实施

---

## 1. 需求背景

`2026-11-05_grade_level_filtering` 引入年级维度后，出题与评测都依赖 `student.grade`。但现状是：

- **学生年级没有任何写入入口**（`StudentConverter` 只读），真实用户永远是 NULL
- 年级为 NULL 时年级过滤整体跳过 → 规则 #11 实际上不生效
- 学生自己也不知道"没设置年级"，更无从补全

上一轮联调靠手工 SQL 造数验证，说明这个缺口必须补上。

## 2. 核心目标

1. 学生端个人中心可**设置/修改年级**（1–12）
2. 未设置时明确展示「未设置年级」，并提供入口
3. **未设置年级不允许创建学习目标**——年级是后续计划与内容过滤的前提，先建目标再补年级会导致计划按"全年级"生成

## 3. 功能范围

### 包含

| 模块 | 内容 |
|------|------|
| 后端接口 | `PUT /api/student/profile/grade`，body `{ "grade": 1..12 }` |
| 后端校验 | 年级必填、1–12；学生记录不存在 → `STUDENT_NOT_FOUND` |
| 目标创建拦截 | `GoalServiceImpl.createGoal` 前置校验学生年级非空，否则 `GRADE_NOT_SET` |
| 学生端 | 个人中心年级行：已设置显示"初三"，未设置显示"未设置年级"；点击弹年级选择器 |
| 学生端 | 创建目标前校验年级，未设置时按钮禁用并提示 |
| 产品规则 | #11 增补"学生可自行设置/修改年级"；#1 增补"未设置年级不可创建目标" |

### 不包含

- 年级变更后**历史数据重算**（不重算：已有计划/作业保持原状，新生成内容按新年级过滤）
- 管理端修改学生年级（Demo 不提供）
- 根据已有知识点/章节自动推断年级
- 学生年级变更审计日志（Demo 规模不做）

## 4. 隐性约定检查

| 约定 / 规则 | 是否涉及 | 说明 |
|------|---------|------|
| 产品规则 #7 学生登录态 | ✅ | `studentId` 只从 `StudentContext` 取，不接受客户端传 |
| #1 统一响应 | ✅ | `Result<Void>` |
| #2 异常处理 | ✅ | 业务异常统一 `BusinessException` + `ErrorCodes` |
| #9 学习记录只读 | ✅ | 本 change 不改历史记录 |
| 产品规则 #11 年级维度 | ✅ | 年级编码仍为 1–12，落库为字符串（沿用 `student.grade` VARCHAR） |

## 5. 风险评估

| 风险 | 等级 | 缓解 |
|------|------|------|
| 已有用户的 `grade` 为 NULL，升级后创建目标直接报错 | 中 | 前端在个人中心显著提示"未设置年级"；错误码文案引导"请先设置年级" |
| 年级被随意修改，导致内容难度跳变 | 低 | 允许修改（学生升学是正常需求）；历史数据不重算，避免追溯混乱 |
| 前端未同步本地缓存，需重新登录才生效 | 中 | 设置成功后立即更新 Pinia store + Storage，无需重登 |
