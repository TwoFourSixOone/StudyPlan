# Proposal：每日作业核心流程

> **Change 名称**：`2026-11-02_homework_core_flow`  
> **创建日期**：2026-11-02  
> **状态**：草案

---

## 1. 需求背景

当前系统已完成：
- 后端基础设施（JWT 鉴权、统一响应结构、全局异常处理）
- 学生登录与认证
- 数据导入功能（题库、知识点、先修关系、课程标准）
- 学习目标管理
- 掌握度状态管理（公式引擎、状态更新、查询接口）

下一步需要实现**每日作业系统**，跑通"设定目标 → Agent 规划每日计划 → 完成每日作业 → 知识点评测 → 掌握度更新"的核心学习闭环。

本次 Change 聚焦于**每日作业核心流程**，实现从出题到批改的基础闭环，为后续错题管理和举一反三新题生成提供数据基础。

---

## 2. 核心目标

1. **出题 Agent 生成每日作业**：根据学生当前掌握度状态，由 Agent 生成结构化作题目
2. **每日作业下发**：学生端查看当日作业列表，支持按日期浏览
3. **学生作答提交**：逐题提交答案，记录作答时间
4. **自动批改**：客观题自动判对错
5. **掌握度更新**：调用已实现的 MasteryService，按作业权重（0.4）更新知识点掌握度

---

## 3. 功能范围

### 包含（In Scope）

| 功能点 | 说明 |
|--------|------|
| 出题 Agent调用 | 构造输入（知识点列表 + 掌握度），调用 Agent 生成题目。需 subjectId 参数定位 active goal（NEW-3） |
| Agent 输出结构化校验 | 校验 Agent 返回的 JSON 是否符合 Schema，失败重试（最多 2 次） |
| Agent 降级处理 | 重试失败后返回默认计划，记录降级日志 |
| 每日作业存储 | 将生成的作业存入 `daily_plan` 表 |
| 作业下发接口 | 学生端按科目 + 日期查询当日作业列表（NEW-3: 新增 subjectId） |
| 作答提交接口 | 学生逐题提交答案，存入 `homework_submission_detail` 表 |
| 自动批改逻辑 | 客观题（选择题、填空题）自动判对错 |
| 掌握度更新调用 | 批改完成后调用 `MasteryService.updateMasteryFromHomework` |
| 作业状态管理 | 作业状态流转：`pending_generation` → `pending` → `in_progress` → `completed`（适配 V1 schema） |

### 不包含（Out of Scope）

| 功能点 | 说明 | 归属 Change |
|--------|------|------------|
| 错题管理（艾宾浩斯周期） | 到期错题重做、暂停与重新入队 | Change 2 |
| 举一反三新题生成 | Agent 生成新题、相似度校验 | Change 3 |
| 专项评测 | 集中评测任务 | 独立 Change |
| 试卷上传与解析 | OCR 切题、归因 Agent | 独立 Change |
| 计划调整 | 触发信号检测、调整 Agent | 独立 Change |

## 4. 隐性约定检查

| 约定编号 | 约定内容 | 本次如何遵循 |
|----------|----------|-------------|
| #1 | 统一响应结构 `Result<T>` | HomeworkController 所有接口返回 `Result<T>` |
| #2 | 异常处理规范 | 业务异常抛出 `BusinessException`，由全局异常处理器捕获 |
| #3 | 分页参数规范 | 作业列表按日期单日查询，题量有限（≤ 15），不分页；分页约定适用于历史列表（后续 Change）（NEW-5） |
| #4 | 时间格式规范 | 实体使用 `LocalDateTime`，前端展示 `yyyy-MM-dd HH:mm:ss` |
| #9 | @Transactional 指定 rollbackFor | Service 层事务方法显式指定 `rollbackFor = Exception.class` |

**新增隐性约定**：
- 出题 Agent 的输入必须包含学生当前掌握度状态，避免生成过难或过易的题目
- 每日作业生成后，若学生未提交，允许重新生成（覆盖旧作业），但需记录降级日志
- 批改完成后必须调用掌握度更新，确保学习行为能反映到掌握度状态

**敏感信息管理规范**：
- 所有密钥、Token 等敏感信息**仅通过环境变量或密钥管理服务注入**
- **严禁**出现在任何工件文件（proposal/design/tasks）、配置模板、日志、代码注释中
- 开发环境使用 `application-local.yml`（已加入 `.gitignore`，不提交版本库）
- 生产环境使用环境变量或 K8s Secret / 云密钥管理服务

## 6. 风险评估

| 风险项 | 风险等级 | 缓解措施 |
|--------|----------|----------|
| Agent 输出不稳定 | 高 | 强制结构化校验 + 重试机制 + 降级策略 |
| Agent 响应超时 | 中 | 设置超时时间（30s），超时后触发降级 |
| 批改逻辑错误 | 低 | 客观题答案明确，批改逻辑简单 |
| 掌握度更新失败 | 低 | 调用已实现的 MasteryService，有事务保障 |
| 并发提交冲突 | 中 | 使用状态机校验控制并发更新（V1 无 version 字段，BLOCK-5 调整） |
| 无有效学习目标 | 低 | 查询 active goal 失败时抛 LEARNING_GOAL_NOT_FOUND(1077)，提示用户先设定目标（IMP-E）。所有接口统一传 subjectId 定位 goal（OBS-1） |
| 降级处理失败 | 低 | 更新 daily_plan.status=cancelled，记录日志，抛异常（IMP-F） |
| 越权提交他人 plan | 低 | submitAnswer 通过 planId 直查 + goal.studentId 归属校验（OBS-2） |

## 7. 验收标准

1. **出题 Agent 调用成功**：能根据知识点 + 掌握度生成结构化题目
2. **Agent 输出校验通过**：不符合 Schema 的输出能正确识别并重试
3. **降级策略生效**：重试失败后能返回默认计划并记录日志
4. **作业下发接口可用**：学生端能按日期查询当日作业
5. **作答提交接口可用**：学生能逐题提交答案
6. **自动批改正确**：客观题批改准确率 100%
7. **掌握度更新成功**：批改后掌握度按公式更新，变更日志可追溯
8. **单元测试覆盖**：核心逻辑测试覆盖率 ≥ 80%
