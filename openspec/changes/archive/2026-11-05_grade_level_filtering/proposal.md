# Proposal：题目与知识点年级维度过滤

> **Change 名称**：`2026-11-05_grade_level_filtering`
> **创建日期**：2026-11-05
> **版本**：v2（2026-11-10 审核后修订）
> **状态**：待实施（产品规则 #11 已落盘，2026-11-10）

---

## 1. 需求背景

学生端现有出题只按**科目 → 知识点 → 掌握度**收敛，没有年级维度。知识点挂在科目下，三年级的数学与高三的数学共用同一棵知识点树，导致低年级学生可能被推到超前内容、高年级学生被推回小学知识。

`Student` 已有 `grade` 字段（`VARCHAR(20)`），但**全库没有任何写入点**——`StudentConverter` 只读不写，实际值只能靠手工 SQL 设置（Demo 阶段）。这一点在 v1 中被忽略，v2 必须显式处理，否则功能上线后"看起来没生效"。

**需求来源**：用户反馈"不同年级的学生应看到适合自己年级的题目"。

## 2. 核心目标

1. 知识点可声明**适用年级范围**（`grade_range`）
2. 题目可标注**所属年级**（`grade`），缺省时继承所属知识点
3. 出题（作业 / 评测）按**学生年级**收敛内容池
4. 数据导入支持年级字段并逐条校验
5. 管理端可见、可筛选

## 3. 需求依据与边界（v2 新增）

**产品文档现状**：v1 提交时 `docs/product/index.md` 中**没有年级维度**——规则 #3（每日作业）未提年级，#8（知识点治理）只规定三级结构与状态，#10（导入）的字段清单无年级。这构成本 change 的边界阻塞。

**已解决（2026-11-10）**：经确认，产品规则 **#11「年级维度与内容匹配」已落盘**至 `docs/product/index.md`（含术语表新增「年级」条目、维护规则第 8 条）。本 change 因此获得唯一依据，可进入 apply。

**与既有规则的关系**：

| 规则 | 关系 |
|------|------|
| 规则 #3 每日作业 | 年级过滤只**收窄内容池**，不改变 15 题 / 单知识点 4 题 / 原题优先的配额算法 |
| 规则 #8 知识点治理 | `grade_range` 是知识点元数据，与 `status`、`subject` 同级；待校对知识点同样可标注年级 |
| 规则 #10 数据导入 | 年级字段为**可选**，旧 JSON 向后兼容；非法值按逐条校验失败处理 |

## 4. 功能范围

### 包含

| 模块 | 内容 |
|------|------|
| 数据库 | `knowledge_point.grade_range VARCHAR(20)`、`question_bank.grade TINYINT`（V11 脚本，含回滚） |
| Entity | `KnowledgePoint.gradeRange`、`QuestionBank.grade` |
| 工具类 | `GradeMatcher`：学生年级归一化 + 范围解析 + 匹配判定 + 空值降级 |
| 作业链路 | ①过滤传给 Agent 的**知识点列表** ②降级处理器取题过滤 |
| 评测链路 | `selectActiveByKp` 候选集过滤 |
| 导入 | 解析 `gradeRange` / `grade`，非法值写 `data_import_error_log` 且不阻塞其他记录 |
| 管理端 | 知识点列表、题目列表展示年级；列表支持按年级筛选 |
| 文档 | `docs/product/index.md` 增补年级规则；`docs/architecture/index.md §5.4` 补字段映射 |

### 不包含

| 项 | 理由 |
|----|------|
| `SubjectVO.availableGrades`（原 v1 Task 2） | 无消费方（学生端年级来自学生档案，管理端不需要），且按科目聚合会造成 N+1，**砍掉** |
| 相邻年级 ±1 自动扩展 | 语义模糊（扩展到哪一档？多个知识点各扩各的会导致配额错乱），v2 改为**整体降级**（见 §5） |
| 错题重做的年级过滤 | 复习旧年级知识是合理学习行为，不做限制 |
| 题库在线录题/编辑 | 产品 §3 已明确不做 |
| 学生年级的设置 UI | 当前无写入入口，Demo 阶段手工 SQL；后续单独 change |
| 跨年级推荐、年级维度统计报表 | 本期不做 |
| 知识点/题目 Prompt 改造 | 年级过滤在后端完成，Agent 不感知年级 |

## 5. 过滤语义（统一口径，v2 核心修订）

v1 同时存在"严格过滤"与"软过滤 ±1"两种说法，自相矛盾。v2 统一定义为 **「严格优先 + 整体降级」**：

```
1. 学生年级为空 / 无法归一化  → 不过滤（保持现状）
2. 按学生年级严格过滤内容池
3. 若过滤后内容池为空（会导致当天无法出题）
   → 关闭年级过滤，用全量池继续，并记 WARN 日志
4. 不做逐题/逐知识点 ±1 扩展
```

选择理由：

- **不做 ±1**：作业要满足"单日 ≤15 题、单知识点 ≤4 题、原题优先"的配额体系，逐项扩展会让不同知识点落在不同年级档，配额语义失控
- **必须兜底**：严格过滤若把池子清空，学生当天就没有作业，比"看到一点超纲题"更糟
- **边界清晰**：要么按年级，要么不按年级，便于测试与解释

## 7. 风险评估

| 风险 | 等级 | 缓解 |
|------|------|------|
| **学生年级无写入入口**，功能默认不生效 | 高 | Demo 阶段手工 SQL 造数；Task 0 明确记录；验收必须包含"设置年级前后对比" |
| 存量知识点/题目无年级数据，过滤实际不生效 | 高 | 未标注 = 全年级通用（向后兼容）；导入时补齐示例数据 |
| 过滤导致某年级内容池过小 | 中 | 整体降级兜底；日志记录降级次数，供后续调数据 |
| 知识点用**名称**关联科目（`knowledge_point.subject` 存科目名），聚合易错 | 中 | 过滤按知识点自身字段进行，不参与"科目录入"逻辑，规避名称关联 |
| 改动落在 `HomeworkServiceImpl`（已 1130 行 / 20 依赖） | 中 | 过滤逻辑放进 `GradeMatcher` 纯函数，Service 只增加"筛 kpList"一行，不再膨胀 |
| 管理端列表 VO 改动影响既有页面 | 低 | 字段为新增，前端列可选展示 |

## 附录 A：产品规则 #11 定稿（已于 2026-11-10 落盘）

> 已写入 `docs/product/index.md`（规则 #11 + 术语表「年级」+ 维护规则第 8 条）。以下为定稿正文，实现必须与之保持一致。

```markdown
### 规则 #11：年级维度与内容匹配

- **规则描述**：知识点可声明适用年级范围，题目可声明所属年级；系统按学生年级收敛出题内容池。
- **年级编码**：1–6 小学、7–9 初中、10–12 高中，以整数表示。
- **数据来源**：知识点 `grade_range`（可空，空表示全年级通用）；题目 `grade`（可空，空表示继承知识点）。
- **边界条件**：
    - 学生年级为空或无法识别时，不做年级过滤。
    - 严格过滤后内容池为空时，关闭年级过滤并记录降级日志（保证当日作业可出）。
    - 错题重做不受年级限制（复习旧知识属于合理学习行为）。
    - 年级过滤只影响内容池，不改变每日作业 15 题 / 单知识点 4 题的配额规则。
```
