## 1. 需求背景

后端服务已全部实现（15 个 Change 已归档），管理后端前端（admin-web）已完成并归档。现在需要开发**学生端微信小程序**，作为用户直接交互的入口。

根据产品规则 §1.1(1)，学生端功能包括：
- 微信静默登录 + JWT 鉴权（规则 #7）
- 学习目标设定（规则 #1）
- 计划总览与每日作业查看（规则 #3）
- 知识点评测与掌握度看板（规则 #2）
- 试卷上传（规则 #4）
- 计划调整（规则 #5）

本 Change 聚焦**基础框架搭建**，为后续功能页面开发提供技术底座。

---

## 2. 核心目标

1. **项目初始化**：uni-app (Vue 3) 项目搭建，配置编译目标为微信小程序
2. **登录与鉴权**：微信静默登录 + JWT token 管理（自动刷新、401 重发）
3. **请求层封装**：统一 API 请求工具（baseURL、token 注入、响应解析、错误处理）
4. **路由与导航**：TabBar 配置、页面路由、登录态守卫
5. **通用布局与组件**：底部 TabBar、页面容器、加载状态、空数据提示
6. **登录页面**：微信一键登录 UI + 流程

## 4. 关键业务约束

| 约束 | 来源 | 说明 |
|------|------|------|
| 微信静默登录 | 规则 #7 | `wx.login()` 获取 code，后端换 openid，不强制手机号授权 |
| JWT 双通道刷新 | 规则 #7 | 通道 A：被动捕获响应头 X-Refresh-Token 自动续期；通道 B：401 反应式 wx.login 重登 |
| 401 静默重登 | 规则 #7 | JWT 过期后自动 `wx.login()` 重放原请求（单次，防循环） |
| 启动与页面级校验 | 约定 #16 | onLaunch init 恢复登录态 + TabBar 页 onShow 兜底校验 |
| 统一响应结构 | 约定 #1 | `Result<T>` = `{ code, message, data }` |
| 租户隔离 | 约定 #15 | Demo 阶段固定 tenant `'default'`，后端从 JWT 解析 |
| 分页参数 | 约定 #3 | `page` 从 1 开始，`size` 默认 10 或 20 |
| 时间格式 | 约定 #4 | 展示为 `yyyy-MM-dd HH:mm:ss` |

## 7. 风险评估

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 微信小程序 API 限制 | 中 | 使用 uni-app 跨端 API 封装，减少平台特定代码 |
| JWT 双通道刷新边界 | 中 | 通道 A 被动捕获无额外请求；通道 B 加锁 + 防循环重放 |
| 网络请求并发冲突 | 低 | 登录刷新加锁，避免多次并发刷新 |
| uni-app Vue 3 兼容性 | 低 | 锁定最新稳定版，避免使用实验性特性 |

## 8. 验收标准

1. uni-app 项目成功初始化，可编译至微信小程序
2. 微信登录流程完整（`wx.login()` → 后端 → JWT 存储）
3. JWT 双通道刷新机制生效：
   - 通道 A：被动捕获响应头 X-Refresh-Token 自动续期
   - 通道 B：401 拦截后自动重登并重放原请求（单次，防循环）
4. 并发重登锁正确，重登失败时广播错误并跳转登录页
5. TabBar 导航正确显示（4 个 Tab 页）
6. 启动校验（onLaunch init）+ 页面级兜底（onShow）拦截未登录访问
7. 统一请求工具正确解析 `Result<T>` 结构
8. 登录页面 UI 完整，微信一键登录可用
