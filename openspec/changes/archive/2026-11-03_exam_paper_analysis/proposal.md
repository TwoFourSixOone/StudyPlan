## 1. 需求背景

当前系统已完成：
- 后端基础设施（JWT 鉴权、统一响应结构、全局异常处理）
- 学生登录与认证
- 数据导入功能（题库、知识点、先修关系、课程标准）
- 学习目标管理
- 掌握度状态管理（公式引擎、状态更新、查询接口）
- 每日作业核心流程（Agent 出题 → 生成 → 提交 → 批改 → 掌握度更新）
- 错题管理系统（艾宾浩斯周期调度、掌握度联动暂停/重新入队）
- 举一反三新题生成（完整配额逻辑、Agent 生成、相似度检测）
- 专项评测系统（评测创建、批改、掌握度更新、错题入队、历史查询）

下一步需要实现**试卷上传与异步解析系统**，跑通"上传试卷 → OCR 切题 → 归因 Agent 知识点归因 → 掌握度更新 → 错题入队 → 查看分析结果"的完整学习闭环。

根据产品规则 #4，试卷必须按科目上传；上传后进入异步解析流程，先通过视觉模型（OCR + 版面分析）切题得到题目列表，再由归因 Agent 逐题做知识点归因，不直接让 LLM 输出"薄弱点总结"。

---

## 2. 核心目标

1. **试卷上传**：学生按科目上传试卷图片（支持多张图片，每张对应试卷的一页）
2. **异步解析任务**：上传后创建异步解析任务，通过 Redis 队列 + 线程池管理
3. **OCR 切题**：调用腾讯云 OCR SDK 识别试卷内容，按题目边界切分
4. **归因 Agent**：对每道题目进行知识点归因（映射到知识点 ID）
5. **成绩录入**：学生手动录入每道题的对错/得分（试卷上传不自动批改）
6. **掌握度更新**：成绩录入后按考试权重（W_source=1.0）更新知识点掌握度
7. **错题入队**：成绩录入后答错的题目自动进入错题队列
8. **解析进度查询**：学生可查询解析任务的实时进度
9. **分析结果查看**：查看试卷分析结果（逐题归因、得分）

## 4. 关键业务约束

| 约束 | 来源 | 说明 |
|------|------|------|
| 试卷按科目上传 | 规则 #4 | 上传时必须指定 subjectId |
| 防重复上传 | BLOCK-4 修复 | 唯一索引 (student_id, subject_id, exam_date, tenant_id)——同一学生同一科目同一天只能传一份试卷 |
| 试卷不自动批改 | BLOCK-6 修复 | 上传后仅做 OCR+归因，学生需手动录入每题对错/得分后触发掌握度更新 |
| OCR 切题失败重试 | 规则 #4 | 最多重试 2 次（总共 3 次尝试），失败后保留原图并标记待人工处理 |
| 归因 Agent 重试 | 规则 #6 | 最多重试 2 次（总共 3 次尝试），与 OCR 切题重试独立计数 |
| 待人工归因 | 规则 #4 | 未识别知识点的题目标记为 pending_manual_review |
| 掌握度权重 | 规则 #2 | W_source = 1.0（考试），高于作业（0.4）和评测（0.7），成绩录入后触发 |
| 错题来源 | 规则 #3 | ErrorQuestionSourceType.EXAM，sourceId = exam_paper_id，成绩录入后触发 |
| D_norm 取值 | 规则 #2 | 全部来自 question_bank.difficulty（题库原题，可信） |
| 数据不可变 | 规则 #9 | 分析结果一旦生成，只读不删 |
| 文件存储策略 | - | 通过 application.yml 配置 local/cos，默认 local；策略模式实现 |
| 异步队列 | - | Redis Queue + Worker 线程池（corePoolSize=3），队列名 exam_analysis_queue |

## 5. 隐性约定检查

| 约定 | 影响 |
|------|------|
| #1 统一响应 | Controller 返回 `Result<T>` |
| #2 异常处理 | Service 抛 `BusinessException`，Controller 不 try-catch |
| #3 分页参数 | 历史列表 `page` 从 1 开始，`size` 默认 10 |
| #4 时间格式 | 使用 `LocalDateTime`/`LocalDate` |
| #9 rollbackFor | 批改+掌握度更新在同一事务内 |
| #10 事务边界 | 文件上传/OCR/Agent 调用在事务外，仅数据库写入在事务内（TransactionTemplate） |
| #11 并发保护 | exam_paper 按 `(student_id, subject_id, exam_date, tenant_id)` 唯一索引保护（防重复上传同一份试卷） |
| #12 超时降级 | OCR/Agent 调用设置 30s 超时，超时触发降级 |
| #13 UNIQUE 索引 | exam_paper `uk_student_exam`（同一学生同一科目同一天唯一） |
| #14 Agent 异常分层 | OCR/Agent 技术异常与业务异常分层处理 |

## 6. 风险评估

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| OCR 切题不准确 | 高 | 重试 2 次（共 3 次）；失败后标记待人工归因；保留原图；使用腾讯云官方 SDK |
| 文件上传与 DB 不一致 | 中 | 文件上传在事务外，DB 写入失败时孤儿文件定期清理 |
| 归因 Agent 失败 | 中 | 重试 2 次；失败后标记待人工归因；记录降级日志 |
| 文件上传失败 | 中 | 本地存储 + 腾讯云 COS 双备份；上传失败返回明确错误 |
| Redis 队列阻塞 | 低 | 设置队列超时（30s）；降级为同步处理 |
| 掌握度更新失败 | 低 | 事务保证原子性；失败回滚 |
| 并发上传冲突 | 低 | 唯一索引 (student_id, subject_id, exam_date) + DuplicateKeyException 捕获 → 返回 EXAM_PAPER_DUPLICATE |
| 腾讯云 OCR 配额限制 | 低 | 添加限流；失败后降级为本地 OCR（后续扩展） |
| 大文件上传超时 | 中 | 限制单张图片大小（≤ 10MB）；压缩处理 |

## 8. 验收标准

1. 学生可成功上传试卷图片（按科目分类，支持多张）
2. 上传后创建异步解析任务，返回 taskId（同一科目同一天防重复上传）
3. OCR 切题成功，题目列表正确（使用腾讯云官方 SDK）
4. 归因 Agent 成功，知识点归因正确
5. 学生可手动录入每道题的对错/得分（成绩录入接口）
6. 成绩录入后掌握度按公式更新（W_source=1.0），mastery_change_log 有记录
7. 成绩录入后答错题目自动进入 error_question（source_type='exam'）
8. 解析进度可查询（pending/processing/completed/failed）
9. 分析结果详情可查看（逐题归因、得分）
10. 分析结果历史列表可分页查询
11. 切题/归因失败时标记待人工归因，不阻塞流程
12. 文件存储服务可切换（local/cos，策略模式）
13. Worker 线程池（coreSize=3）并发消费 Redis 队列
14. 全部单元测试通过，Service 层覆盖率 ≥ 80%
