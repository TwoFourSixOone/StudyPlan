# Proposal：试卷解析可靠性：上传页序、卷面题号保真、清晰度门槛

> **Change**：`2026-11-17_exam_parse_reliability`　**状态**：已实施（2026-11-17，T7 联调待跑）

## 背景（2026-11-17 真实案例）

学生上传 2025 全国卷数学（4 张图）：第 1、2 页是 **500×684 / 500×657 的低清截图**，第 3、4 页是 1242px 原图。`exam_paper.id=4` 的解析结果出现三类问题：

1. **编题**：卷面第 2 题（`U={1..8}`、`A={1,3,5}`、求 `∁UA` 元素个数）被改写成另一道题（`U={1..7}`、`A={1,3,5,7}`、"求 A 的补集"，选项变成集合），并按「学生答 B / 标准答案 A」判错；同页第 1、3、4 题也被替换成标准变体（`(1+5i)i`→`(1+i)²`、`√7`→`√3`、`2tan(x−π/3)`→`tan2x`）。
2. **题号错位**：4 张图并发上传，服务端按**请求到达顺序**追加（本次为 第4页→第1页→第3页→第2页），整卷解析又**忽略卷面题号、按图序重排 1..N** → 卷面第 17/18/19 题变成 App 的 1/2/3 题。
3. **丢题**：第 16 题（数列）整题未落库，18 题 ≠ 卷面 19 题，**无任何告警**。
4. **作答归属不清**：卷面同时存在学生作答与老师批改——卷首 `-5 -5 -12 -12 = -34`、圈出的 `116`、日期 `2025.6.7`、时间 `21:00-23:00`、签名 `Jasmine`；本卷选择题是**在选项上打勾**作答，老师也在正确选项上打勾（第 2 题 C、第 3 题 D 都是两个勾叠在同一选项）。当前 Prompt 只区分「印刷内容 vs 学生手写」，没有「勾选 = 作答」「老师勾 = 批改」的规则：第 2 题学生勾了 C，库里记成 B；第 3 题学生勾了 D，库里记成印刷公式 `a²+b²=c²`。**另有一类红笔批改卷**（题号左侧红笔字母 = 正确答案、红笔解题过程与 √× 点缀），整页没有学生作答——红笔答案绝不能填充 `studentAnswer`。

同一组 4 张图（文件 hash 完全一致）当天被上传 4 次（换考试日期绕过 1131），解析结果分别是 **14 / 19 / 8 / 18 题**，每次编的题都不同 —— 不是偶发，是系统性问题。假题已写入 `error_question`（`source_id=4`）并参与掌握度更新。

> `2026-11-17_glm_ocr_grounding` 已提供 OCR 文本 grounding。`ZHIPU_API_KEY` 已在**机器级环境变量**配置，但 10:38 那次解析所在的 Java 进程早于配置启动、不会继承新变量，实际仍是纯视觉解析（**重启应用后才生效**）。实测 GLM-OCR 对 500×684 页同样把 `√7` 读成 `√2`、`(1+5i)i` 读成 `(1+50)`，但能保住「U/A/元素个数」的题目结构——所以 OCR 能挡住"编题"，挡不住低清误读。

## 目标

1. **页序可控**：并行上传（约定 #30 不变）下，图片顺序 = 学生选择顺序，模型按正常页序阅读。
2. **题号保真**：**保留卷面题号，不再按图片顺序重排**；列表与详情一律按题号升序展示（卷面第 17 题就是第 17 题）。
3. **低清图拦截**：分辨率不足的图片在入口被拒，提示"上传原图/重拍"，避免"读不清就编题"。
4. **缺题可见**：模型报告整卷题数与卷面题号，服务端校验缺口/重复并写入详情页告警 + 降级日志，不再静默。
5. **作答归属**：明确区分**学生作答 / 老师批改 / 印刷内容**；**先看颜色（红笔默认老师批改）**，黑/蓝笔的**勾选/圈选/划线就是学生作答**（映射为选项标签）；红笔写的选项字母（正确答案）、解题过程、分数、√/× 不进入题干/学生答案/正确答案依据；整页只有红笔批改 → 全部 `blank`；分不清归属的作答标 `unreadable`，不臆造。
6. **静默丢题修复**：`explanation` 长度上限与 schema 对齐；被丢弃的题计入告警。

## 方案

```
上传：每张图带 pageNo（1..8）→ exam_paper.image_page_nos（与 image_urls 等长）
解析：按 pageNo 排序后的 URL 列表发送；旧数据（page_nos NULL）按到达顺序
编号：每题 paperNo（卷面题号）直接落 question_index，列表按题号升序；不再按图序重排
      （模型未给全/重复/越界时回退按图片顺序 1..N，并告警）
入口：长边 < 600 或 短边 < 500 → 1193（带实际尺寸与最低要求），阈值可配置
作答归属：Prompt 先看颜色（红笔默认老师批改）；黑/蓝笔的勾选选项 = 学生作答；
      老师勾/红笔字母/解题过程只表示对错或讲解，一律忽略；整页只有红笔 → 全部 blank；
      学生答案无法分辨 → unreadable；OCR 文本中混入的手写/批改片段不得并入题干
完整性：模型额外输出 paperQuestionTotal → 识别数≠总数/缺号/重复
      → exam_paper.remark（详情页 imageWarning）+ 降级日志 parse_question_gap
输出：单题 explanation 上限 1000 → 1500（与 schema 一致）；被丢弃的题数写告警
```

## 范围

  `ExamPaperController`（`pageNo`）、`ExamPaperServiceImpl`（排序、解析、配图裁剪、详情、学习记录）、
  `ExamParseAgentImpl`（paperNo/total、题号保真、丢弃计数、作答归属兜底清洗）、
  `ExamParseServiceImpl`（编号回退与缺口告警）、`AgentOutputValidator`（explanation 上限）、`ErrorCodes`（1193）
- **Prompt / Schema**：`exam_parse_paper_v1.txt`（题号/总数、三类笔迹归属、OCR 手写例外）、`exam_parse_schema.json`
- **OCR 预处理**：`RedInkSuppressor`（OCR 前刷白红笔，纯视觉仍用原图）
- **小程序**：`api/exam.ts`（pageNo + 分辨率常量）、`ExamUpload.vue`（带入 pageNo、上传前预检）、
  `ExamDetail.vue`（题号展示「第 X 题」）
- **文档**：产品规则 #4、隐性约定 #38/#39/#40

## 不包含

- **编题内容级检测**（题干与 OCR 文本比对）：需 OCR 接通后用真实样本调阈值，另立 change
- **存量试卷不回填**：含 `paperId=4` 的错误数据清理、错题/掌握度回滚与重解析
- "已完成试卷重新解析"入口（依赖上一条的回滚能力）
- 判分口径、掌握度公式、归因规则

## 验收（实现后写 verify.md）

- 400×300 页 → 上传返回 1193，提示包含实际尺寸与最低要求（联调期阈值 600/500，500×684 放行但仍有误读风险）
- 4 张 1242px 图乱序并发上传 → `image_urls`/`image_page_nos` 落在同一数组下标
- **题号保真**：卷面第 17 题落库 `question_index=17`，详情页按 1..19 升序、显示「第 17 题」，不再变成第 1 题
- 模型未给全题号/题号重复 → 回退按图片顺序 1..N，并在详情页提示「未能识别卷面题号，已按图片顺序编号」
- 缺第 16 题时：`exam_paper.remark` 含「应有 19 题 / 识别到 18 题 / 缺第 16 题」，详情页展示；列表保留题号缺口（1..15,17..19）
- **作答归属**：卷首 `-5…/-34`、`116`、日期/时间/签名不进任何题干或学生答案；第 2 题 `studentAnswer=C`、第 3 题 `studentAnswer=D`（学生勾选，而不是 B / 印刷公式 `a²+b²=c²`）；老师勾只表示对错，不能把学生未勾选的选项记成学生答案（无法分辨 → `unreadable`）；老师 √/× 不改变 `correctAnswer`
- 1200 字解析不再被丢弃；被丢弃题计入告警与降级日志
- 旧数据（page_nos NULL / question_index 1..N）解析与展示行为不变
- `mvn test` 全绿
