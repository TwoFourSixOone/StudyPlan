# Proposal：学习记录查询与回溯系统

> **Change 名称**：`2026-11-03_learning_record_query`  
> **创建日期**：2026-11-03  
> **状态**：草案 v3（修复 BLOCK-C）

---

## 1. 需求背景

当前系统已完成：
- 后端基础设施（JWT 鉴权、统一响应结构、全局异常处理）
- 学生登录与认证
- 数据导入功能（题库、知识点、先修关系、课程标准）
- 学习目标管理
- 掌握度状态管理（公式引擎、状态更新、查询接口）
- 每日作业核心流程（Agent 出题 → 生成 → 提交 → 批改 → 掌握度更新）
- 错题管理系统（艾宾浩斯周期调度、掌握度联动暂停/重新入队）
- 举一反三新题生成（完整配额逻辑、Agent 生成、相似度检测）
- 专项评测系统（评测创建、批改、掌握度更新、错题入队、历史查询）
- 试卷上传与异步解析系统（OCR 切题、归因 Agent、掌握度更新、错题入队）
- 计划调整系统（触发信号检测、调整 Agent、计划 diff、用户确认）

下一步需要实现**学习记录查询与回溯系统**，提供完整的学习行为数据查询与追溯能力。

根据产品规则 #9，系统完整记录学生的全部学习行为数据（统称"学习记录"），作为掌握度变更的依据来源与学习效果的回溯凭证。学习记录包含每日作业提交记录、专项评测结果、考试试卷分析结果三类数据。

---

## 2. 核心目标

1. **学生端学习记录列表**：按日期浏览历史学习记录（三次分页查询 + 归并排序，避免内存分页）
2. **学习记录详情查看**：查看作业提交记录、评测结果、试卷分析结果（路径含 recordType，语义明确）
3. **管理端学习记录查询**：按学生 + 时间范围 + 记录类型查询
4. **掌握度变更追溯链**：行为 → 状态变化的完整追溯
5. **数据只读不删保障**：学习记录与系统日志只追加不删除

| 风险 | 等级 | 缓解措施 |
