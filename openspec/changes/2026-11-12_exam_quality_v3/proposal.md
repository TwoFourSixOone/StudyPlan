# Proposal：试卷解析 v3（整卷单次调用 / 答题卡 / 配图 base64）

> **Change 名称**：`2026-11-12_exam_quality_v3`
> **状态**：已实施，验证通过（见 `verify.md`），待归档

---

## 1. 背景（真实卷反馈）

| 现象 | 根因 |
|------|------|
| 详情页配图位置**空白**（点了只有白框） | 配图只存文件 URL（`http://localhost:8080/uploads/...`），端口与后端（80）不一致、真机 localhost 不可达 → image 加载失败 |
| 明明是多选题被判成单选 | 逐图解析时看不到卷面「多选」标注（可能在另一页/另一张图），模型按单选出答案 |
| 题目/图形可能跨页，答案可能写在答题卡 | 逐图独立解析，模型看不到其他页；答题卡页被当作"无题目"直接忽略 |
| 配图裁剪不准 | 逐图发给模型时只能看到本图局部，坐标准确率低 |

用户明确要求：**所有图片一次性发给大模型**；**裁剪后的配图转 base64 落库**，页面直接加载。

## 2. 目标

1. 整卷解析改为**一次调用传全部图片**（跨页题目合并、图形定位、答题卡答案匹配、多选判断）。
2. 题目配图 **base64 落库**（新增 `exam_question.figure_base64` MEDIUMTEXT），详情页优先用 base64 渲染。
3. 单次调用失败 → **自动回退逐图解析**（可用性优先）。
4. 请求体控制：8 张原图超 6MB 时降采样到 1600px/82 再发送；输出上限显式给足 8000 token。
5. 解析/轮询超时放宽：整卷预算 300s、前端轮询 5 分钟。

## 3. 范围

### 包含

- 新 Prompt `exam_parse_paper_v1.txt`（跨页合并、答题卡、多选、全卷连续题号、figureRect 相对图形所在图）
- `ExamParseAgent.parsePaper(images, context)` + `ExamParsePaperContext`
- `ExamParseServiceImpl`：`exam.parse.single-call`（默认 true）→ 整卷调用，空/异常回退逐图
- `ImageDownscaler`（>6MB 降采样）；`AgentScopeConfig.maxTokens=8000`
- `V14__add_exam_question_figure_base64.sql` + 实体/VO/前端 base64 渲染（`figureBase64 || questionImageUrl`）
- 前端轮询 90 → 150 次（5 分钟）

### 不包含

- 存量试卷不回填（仍只有旧解析结果；需重解析）
- 不改逐图解析逻辑（保留为回退路径）
- 不做"答题卡单独建模"（答题卡答案由同一 Prompt 匹配，不单独存表）

## 4. 风险

| 风险 | 等级 | 缓解 |
|------|------|------|
| 单次调用输出超长被截断 | 中 | maxTokens 8000 + 4 张图实测 21.8s 可完成；截断时 JSON 校验失败 → 重试 → 仍失败回退逐图 |
| 8 张原图请求体过大 | 中 | >6MB 降采样 1600px/82；实测 4 图 0.89MB 请求体 21.8s |
| 答题卡匹配错题号 | 中 | Prompt 要求按题号对应；无法匹配时 blank（不臆造） |
| 单次调用慢（8 图可能 60–120s） | 中 | 任务预算 300s、前端轮询 5 分钟；失败回退逐图（逐图 6.5–8s/图） |
| 新增列 | 低 | 可空 MEDIUMTEXT，存量 NULL → 前端回退 URL；迁移脚本 V14 需在环境执行 |
