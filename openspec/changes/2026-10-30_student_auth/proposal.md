# Proposal：学生登录与 JWT 鉴权

> **Change ID**: `2026-10-30_student_auth`  
> **创建日期**: 2026-10-30  
> **状态**: 待审查

---

## 1. 需求背景

智学伴（StudyMate）项目已完成基础框架搭建（change `2026-10-30_backend_foundation`），现需实现学生端登录与鉴权功能。根据产品规则 #7，学生端通过微信小程序静默登录获取 `openid`，后端签发 JWT 进行接口鉴权。

本 change 负责实现完整的登录流程、JWT 签发与校验、自动刷新机制，为后续所有业务接口提供安全的访问控制。

---

## 2. 核心目标

1. **实现微信小程序登录流程**：后端接收前端传入的 `code`，调用微信接口换取 `openid`
2. **实现 JWT 签发与校验**：基于 `openid` 签发 JWT，包含 `student_id`、`tenant_id` 等关键信息
3. **实现 JWT 自动刷新机制**：过期前 5 分钟内返回新 JWT，过期后返回 401 并支持前端重放请求
4. **实现接口鉴权拦截器**：所有业务接口需校验 JWT，未授权请求返回 401
5. **实现学生自动注册**：首次登录时自动创建学生记录

---

| DTO/VO 类 | 登录请求 DTO、登录响应 VO、学生信息 VO |

## 4. 隐性约定检查

根据 `docs/architecture/implicit-contracts.md`，本 change 需满足：

| 约定 | 实现方式 |
|------|----------|
| 约定 #1：统一响应结构 | 所有接口返回 `Result<T>` 格式 |
| 约定 #2：异常处理规范 | 登录失败抛出 `BusinessException`，由 `GlobalExceptionHandler` 处理 |
| 约定 #7：tenant_id 注入 | JWT 中包含 `tenant_id`，拦截器自动注入查询条件 |
| 约定 #9：@Transactional rollbackFor | 学生注册方法需添加事务注解 |

## 5. 风险评估

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 微信 API 调用失败 | 中 | 添加重试机制（最多 2 次），失败返回明确错误提示 |
| JWT 密钥泄露 | 高 | 密钥通过环境变量配置，不硬编码在代码中 |
| JWT 过期时间设置不当 | 中 | 严格按照产品规则设置为 2 小时，可通过配置文件调整 |
| 并发登录导致数据不一致 | 低 | Demo 阶段不限制，后续通过令牌版本控制 |
| 学生信息泄露 | 中 | 接口返回最小化字段，敏感信息脱敏 |
