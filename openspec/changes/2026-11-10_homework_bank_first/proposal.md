# Proposal：每日作业优先从题库抽题

> **Change 名称**：`2026-11-10_homework_bank_first`
> **创建日期**：2026-11-10
> **状态**：待实施

---

## 1. 背景

当前每日作业的题目只有两条来源：

| 类型 | 来源 | 成本 |
|------|------|------|
| 错题重做（原题） | `question_bank` 抽原题 | 0 |
| 举一反三 / 知识回顾 | `QuestionGenAgent` 现场生成 → `generated_question` | 每次 1~3 次 LLM 调用 |

导入的题库有 12579 道题（每知识点 3~5 道），却只服务"错题重做"和"专项评测"，**新知识点一律现生成**。后果：

- 每次生成作业都要付 LLM 延迟与 token 成本
- 生成题质量不可控，且无人工审核痕迹
- 题库里大量题目长期闲置

## 2. 目标

1. 举一反三、知识回顾**优先**从 `question_bank` 抽题（按知识点 + 年级，排除已做过的题）
2. 题库不足时**由 Agent 生成补充**（保留现有能力，不降低题量）
3. 题量、配额、状态机、降级路径**全部不变**

## 3. 范围

### 包含

- 新增 `BankQuestionPicker`：按 `kpId + 年级 + 排除已答题` 从题库抽 N 道
- 新增按学生查询"已做过的题库题"（`homework_submission_detail` JOIN `daily_plan` JOIN `learning_goal`）
- `HomeworkServiceImpl` 第 7 步（举一反三）、第 8 步（知识回顾）改为题库优先
- 产品规则 #3 更新题目来源表述
- 单测

### 不包含

- 不改变"错题重做"逻辑（本来就取题库原题）
- 不改变配额算法（`HomeworkQuotaCalculator`）
- 不做题目难度自适应（题库题难度固定，由 `difficulty` 字段约束 Agent 侧，不在本次范围）
- 不做题库抽题的随机化/间隔重复调度（下一轮再考虑）

## 4. 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 题库不足时 | **Agent 补足**，不缩减题量 | 保持规则 #3 的"每知识点 2~3 道"体验；题库每知识点仅 3~5 道，排除已做后常常不足 |
| 排除已做过的题 | 是 | 避免同一道题反复出现；跨天也排除 |
| 年级过滤 | 用 `GradeMatcher.matchesQuestion`（题目 grade 为空时回退知识点范围） | 与出题过滤同一口径 |
| 抽题顺序 | 按 `question_id` 升序取前 N | 可预测、可测试；随机化留待后续 |

## 5. 风险

| 风险 | 等级 | 缓解 |
|------|------|------|
| 题库题目质量未经审核，直接进作业 | 中 | 题库有 `status` 字段，`selectActiveByKp` 已只取 active；导入时已有校验 |
| 排除已做导致可用题枯竭 | 中 | 不足时 Agent 补足，题量不变 |
| 同一知识点跨天反复用同一批题 | 低 | 已做排除可缓解；长期需按"掌握度+间隔"调度 |
