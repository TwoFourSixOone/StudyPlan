# Proposal：目标创建生成整段计划骨架 + 自动调整

> **Change 名称**：`2026-11-10_goal_planning_agent`
> **状态**：已实施（待联调）

---

## 1. 背景

产品规则 #1 描述的是"设定目标 → **Agent 规划每日计划** → 完成每日作业"，但实现里**没有规划环节**：

- 创建目标只写 `learning_goal`，`daily_plan` 一行都没有
- 每天 02:00 出题时**临场决定**学哪些知识点（按掌握度排序），没有跨天节奏
- 后果：知识点覆盖无序，`SIG-4`（周期内覆盖不完）长期命中，只能用"暂缓知识点"迂回缓解

## 2. 目标

1. 创建目标时由**规划 Agent** 拆出整段每日计划骨架（每天学哪些知识点、多少题）
2. 每日 02:00 出题**按骨架执行**，骨架缺失才回退到"按掌握度现算"
3. 信号命中时**自动调整**，不需要学生手动确认（保留手动入口兜底）

## 3. 范围

### 包含

- 新增 **PlanningAgent**（`planning_schema.json` + `planning_v1.txt`）：输入真实数据，输出每日计划
- 新增 **PlanSkeletonService**：创建目标后落 `daily_plan` 骨架（幂等；Agent 失败回退模板）
- `V13`：`daily_plan` 增加 `planned_kp_ids`、`planned_question_count`
- `generateDailyHomework` 读取骨架：收窄知识点、按骨架题量出题
- 新增 **AutoAdjustmentTask**（02:30）：检测信号 → 生成方案 → 直接应用
- 产品规则 #1/#3/#5 与 spec 同步

### 不包含

- 预生成题目内容（题目仍当天生成，保证基于最新掌握度）
- 目标周期中途修改后的骨架重排（下次调整会覆盖）
- 多实例分布式锁（幂等靠唯一索引 + 存在性检查）

## 4. 风险

| 风险 | 等级 | 缓解 |
|------|------|------|
| 规划 Agent 输出幻觉知识点 | 高 | Schema 约束 + Service 侧以真实点赞取交集（不在清单内的 ID 会被忽略） |
| 创建目标变慢 | 中 | 骨架只写 DB 不代表出题；Agent 失败立即回退模板 |
| 自动调整误伤 | 中 | 只改未来未开始的计划；历史只读；调整历史可查 |
| 骨架与掌握度脱节 | 中 | 骨架只决定"学哪些知识点"，题目仍按当日掌握度生成 |
