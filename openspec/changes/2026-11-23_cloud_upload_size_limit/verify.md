# Verify：云端上传按 2MB 请求体上限自动压缩

> **Change**：`2026-11-23_cloud_upload_size_limit`　**验证**：2026-11-23（构建 + 本地回归；云端真机待联调）

## 现象 → 根因 → 修复

| 现象 | 根因 | 修复 |
|---|---|---|
| 微信开发者工具（直连本地 `localhost:80`）上传正常 | 本地无网关，后端 multipart 上限 10MB / 业务 9.5MB | — |
| 云托管环境上传失败（约 2MB 量级） | `uni.uploadFile` 走云托管**公网域名**，平台入口对单次请求体有上限（约 2MB），而前端压缩策略是"仅 >800KB 压一次 quality 85"，上限判定用后端的 9.5MB → 超限请求被网关直接拒掉（后端无请求日志） | 云端模式多档压缩到 ≤1.8MB 再上传；仍超限则明确提示不发请求 |

## 实现要点

| 项 | 值 / 行为 |
|---|---|
| 模式判定 | `resolveUseLocal()`：`VITE_USE_LOCAL=true/false` 优先，否则 `DEV` 视为本地（与 `utils/upload.ts` 同源） |
| 云端阈值 | `CLOUD_SAFE_BYTES = 1.8MB`（留 multipart 头/boundary 余量） |
| 压缩梯度 | `quality 85 → 70 → 55 → 45`，达到阈值即停 |
| 超限兜底 | 压缩后仍 >1.8MB → `showError("云端上传单张需 ≤2MB（已自动压缩，当前 x.xMB）：请裁剪或重新拍摄后重试")`，**不发请求** |
| 本地模式 | 不变：`>800KB` 压一次 `quality 85`；上限判定仍为后端 9.5MB |
| 不改后端 | multipart 10MB / 业务 9.5MB 保持不变 |

## 已知取舍

- **只降质量不 resize**：保住长边像素（OCR 分辨率下限仍按原图判定），代价是极端照片可能压不到 1.8MB → 走"提示重拍"分支；
- **本地/云端策略不同**：本地不过度压缩以保识别率；若希望两端一致，可把本地也切到云端阈值（改一处常量即可）。
